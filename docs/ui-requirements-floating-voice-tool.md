**文档版本**：V1.0  
**编写日期**：2026-09-05  
**适用项目**：TerminalVoice  
**依据文档**：`docs/prior-art-research-floating-voice-tool.md`

## 1. 文档目的

本文定义 TerminalVoice 后续需要新增、补全和修改的 UI 界面，以及每个界面必须提供的功能、状态、交互和验收标准。

本需求**不是重新设计一套独立产品界面**，而是以当前代码库已经存在的 UI 为基础进行增量完善：

- 保留现有的悬浮小球窗口 `src/windows/ball/BallWindow.tsx`；
- 保留现有的极简面板窗口 `src/windows/panel/PanelWindow.tsx`；
- 保留现有的 `PreviewPopup` 预览编辑组件；
- 将面板底部已有的「语音技能 / 自定义词典 / 历史记录 / 帮助与关于」四个 Tab 从占位提示改为真实功能页；
- 将当前面板中已有的「服务配置 / 设置触发键 / 选择麦克风 / 交互声音 / 使用时静音系统声音 / 开机启动并隐藏面板」扩展为可用配置流程；
- 保持现有深色炭黑、圆角卡片、毛玻璃悬浮球、底部图标 Tab 的视觉语言，不引入与现有 UI 不一致的复杂后台管理风格。

## 2. 产品 UI 目标

### 2.1 核心用户路径

UI 必须围绕两个核心动作组织：

| 动作 | 用户操作 | UI 结果 |
| :--- | :--- | :--- |
| **说** | 按住 `Right Alt` 说话，松开 | 浮球显示录音状态；识别和整理完成后打开预览，确认后写入当前焦点输入框 |
| **改** | 选中已有文字，按触发键并口述修改要求 | 浮球进入改写状态；显示原文和改写结果；确认后替换原选区 |

### 2.2 UI 设计原则

1. **浮球负责即时反馈，面板负责配置和管理**：用户不需要在主流程中打开复杂设置。
2. **状态优先**：任何录音、识别、AI 整理、错误和暂停状态都必须有明确视觉反馈。
3. **默认路径最短**：首次安装后用户可以直接使用默认配置完成基础流程；需要配置时才进入详情页。
4. **不打断用户输入**：预览、Toast 和错误提示应优先使用轻量浮层；只有不可继续的问题才使用模态对话框。
5. **后端状态唯一权威**：UI 只订阅后端状态和事件，不自行推断运行状态。
6. **可恢复**：失败后允许重试、跳过 AI 整理、切换离线引擎或复制结果，不让用户丢失已识别文本。
7. **中文优先**：界面文案默认使用简体中文；快捷键、模型名、服务商名和错误码保留原文。

## 5. UI-01 悬浮小球

### 5.1 目标

悬浮小球是后台常驻时用户最常接触的入口，负责：

- 显示当前运行状态；
- 暗示当前可执行动作；
- 承载轻量错误和进度反馈；
- 点击打开极简面板；
- 不承载复杂配置和长文本内容。

### 5.2 保留现有结构

保留当前 `BallWindow` 的以下设计：

- 48×48 圆形透明窗口；
- 内部毛玻璃圆盘；
- 外圈光晕；
- hover 放大和 tooltip；
- 使用绿色、蓝色、橙色、灰色区分主要状态；
- 点击通过 Tauri Window API 打开 `panel` 窗口。

### 5.3 状态要求

| 后端状态 | 小球状态 | 视觉要求 | Tooltip/提示文案 |
| :--- | :--- | :--- | :--- |
| `Idle` | idle | 绿色核心点，静态光环 | `就绪 · 按住 Right-Alt 说话` |
| `Recording` | recording | 蓝色麦克风图标，呼吸动画 | `录音中 · 松开上屏` |
| `Recognizing` | thinking | 橙色核心点，脉冲动画 | `识别中…` |
| `Preview` | thinking | 保持橙色，降低脉冲频率 | `等待确认 · 点击打开预览` |
| `Paused` | disabled | 灰色核心点，无激活动画 | `已暂停 · 点击面板恢复` |
| 错误 | error | 红色光环或红色闪烁一次 | 显示短错误信息和 `点击重试` |
| 离线识别 | offline | 绿色/蓝色基础样式，增加离线标记 | `离线模式 · 使用本地模型` |
| 改写录音 | rewrite-recording | 紫色或蓝紫色麦克风图标 | `改写录音中 · 松开提交` |
| 改写识别 | rewrite-thinking | 紫色脉冲 | `正在生成改写结果…` |

> 具体颜色可以复用现有 Tailwind 颜色层级，但必须保证 error、rewrite、offline 与普通识别状态可区分。

### 5.4 交互要求

1. **左键点击**：打开或聚焦极简面板；若当前有待确认预览，则打开预览弹窗。
2. **拖拽**：移动悬浮球位置；拖拽后保存位置；面板打开时定位到悬浮球旁边。
3. **hover**：显示当前状态 tooltip；tooltip 不阻挡桌面输入。
4. **录音期间**：小球不可通过普通点击改变状态，避免误操作；仍允许拖拽。
5. **暂停状态点击**：打开面板，并聚焦到暂停/恢复相关设置。
6. **错误状态点击**：打开面板错误详情；如果存在可重试动作，显示重试按钮。

### 5.5 验收标准

- 后端状态变化后，小球在 300ms 内更新视觉状态；
- 录音中、识别中、预览中、暂停、错误、离线和改写状态可被明确区分；
- 小球点击可以打开面板，不会创建重复窗口；
- 拖拽位置在应用重启后保留；
- 小球不显示 API Key、完整错误堆栈或长文本。

## 6. UI-02 极简面板-首页

### 6.1 目标

极简面板是现有 `PanelWindow` 的主界面，用于快速查看状态和修改高频设置。必须保持当前 380px 左右的紧凑宽度和底部 Tab 布局，避免演变成复杂后台。

### 6.2 顶部栏

保留当前顶部栏结构，并补全实际行为：

| 区域 | 功能 |
| :--- | :--- |
| 状态圆点 | 显示后端服务是否正常；hover 显示当前 `AppStatus` |
| `TerminalVoice` 标题 | 面板拖拽区域 |
| 状态按钮 | 显示当前状态；录音时显示停止/取消动作，非录音时显示就绪状态 |
| 更多按钮 | 打开轻量菜单：检查更新、打开日志目录、重置窗口位置 |
| 最小化按钮 | 隐藏面板，保留托盘和小球运行 |
| 关闭按钮 | 根据产品策略关闭面板或退出确认，不得直接终止后台录音 |
| 主题按钮 | 切换深色/浅色主题，并持久化 `ui.dark` |

### 6.3 主内容区

当前已有设置行全部保留，但改为可用状态：

#### 6.3.1 服务配置

- 显示当前整体配置状态：`未配置`、`已配置`、`配置不完整`、`连接失败`；
- 点击进入 UI-03 服务配置详情；
- 右侧显示当前主路径，例如 `云端 ASR · AI 整理开启`；
- 如果云端不可用但离线模型可用，显示 `已切换离线`；
- 如果没有可用 ASR，显示红色错误状态并提供「去配置」入口。

#### 6.3.2 设置触发键

- 默认显示 `Right-Alt`；
- 点击进入触发键录入状态；
- 支持按键录入、确认、取消和恢复默认；
- 显示冲突提示，例如该按键被系统或其他功能占用；
- 支持在同一项下切换：
  - 按住说话，松开提交；
  - 单击开始，再次单击提交；
- 保存成功后显示短暂 `已保存` 状态。

#### 6.3.3 选择麦克风

- 显示当前设备名；
- 点击展开设备列表；
- 支持刷新设备列表；
- 支持「测试麦克风」按钮和 3 秒输入音量指示；
- 没有设备时显示 `未检测到麦克风`，并提供帮助入口；
- 设备被占用时显示可恢复错误，而不是静默失败。

#### 6.3.4 高频开关

保留当前三项开关：

- `交互声音`：录音开始、结束、错误时是否播放提示音；
- `使用时静音系统声音`：录音期间是否暂时降低或静音系统音量；
- `开机启动并隐藏面板`：启动后是否仅显示小球和托盘。

每个开关需要：

- 点击后立即更新 UI；
- 后端保存失败时回滚到旧值；
- 通过 Toast 说明保存失败原因；
- 不因保存失败阻断其他设置操作。

### 6.4 首页底部提示

保留当前辅助文案位置，但内容根据状态动态变化：

- 默认：`按住 Right-Alt 说话 · 松开上屏`；
- 免提模式：`单击 Right-Alt 开始 · 再次单击提交`；
- 离线模式：`当前使用本地离线模型`；
- 暂停：`服务已暂停 · 点击状态按钮恢复`；
- 配置错误：`请先完成服务配置`。

### 6.5 验收标准

- 首页打开后可以看见当前服务、触发键、麦克风和核心开关；
- 所有已显示的可交互控件都有真实行为，不再出现“待实现”占位；
- 页面不需要滚动即可完成最高频设置；
- 面板关闭或最小化不会影响后台小球和热键监听。

## 7. UI-03 服务配置详情

### 7.1 入口和形式

由首页「服务配置」行进入。优先采用**面板内详情页或从右侧展开的抽屉**，沿用现有圆角卡片和深色主题，不新建完全独立的后台页面。

必须提供返回按钮，返回后保留用户刚刚修改的界面位置。

### 7.2 服务模式总览

顶部显示当前模式：

- `在线优先`：云端 ASR 成功时使用云端，失败后尝试离线；
- `离线优先`：优先使用本地模型，必要时切换云端；
- `仅在线`：云端失败时明确提示不可用；
- `仅离线`：没有本地模型时阻止开始录音并给出下载入口。

默认模式为文档约定的“云端主路径 + 本地离线兜底”。

### 7.3 云端 ASR 配置

字段和功能：

| 字段 | UI 要求 |
| :--- | :--- |
| 服务商 | Select，至少支持当前接入的 provider，并预留扩展 provider |
| Endpoint | OpenAI 兼容或服务商专用 endpoint 输入框 |
| API Key | 密码输入框，默认掩码；支持显示/隐藏，不显示完整明文到日志或 Toast |
| Model | 模型名输入或下拉选择 |
| 语言 | 默认中文，可选择自动检测/中文/英文等 |
| 测试连接 | 调用后端测试，显示成功、失败和耗时 |
| 保存 | 保存单项配置并更新首页状态 |

### 7.4 LLM 配置

用于 AI 文字整理和语音改写：

- Endpoint；
- API Key（掩码显示）；
- Model；
- 超时；
- 是否启用流式响应；
- 测试连接；
- 保存并返回。

必须明确提示：

> API Key 由用户自行配置并保存在本机，不在界面中展示完整密钥。

### 7.5 AI 文字整理模式

提供以下选项：

1. `关闭整理`：识别结果直接进入预览；
2. `原意校对`：修正错别字、标点和明显语病，不改变原意；
3. `自然润色`：改善表达流畅度，保留原始信息；
4. `结构整理`：根据内容补充段落、列表和层次。

每个选项需要有简短帮助说明。默认选项可以为 `原意校对`，但必须允许用户关闭。

### 7.6 离线模型管理

展示本地模型列表：

- 模型名称、语言、大小和能力；
- 未下载、下载中、已安装、校验失败、不可用状态；
- 下载、暂停、继续、删除、重新校验；
- 当前默认模型选择；
- 模型存储位置；
- 磁盘空间不足提示；
- 下载失败重试。

下载进度应显示在配置页中，不占用悬浮球主视觉；下载期间小球 tooltip 可显示简短进度。

### 7.7 验收标准

- 用户可以配置并测试 ASR 和 LLM；
- API Key 永远以掩码显示，错误信息不包含 Key；
- 用户可以开启/关闭 AI 整理并选择三种模式；
- 用户能够判断当前是否具备在线或离线识别能力；
- 云端失败且本地模型可用时，界面能说明已自动切换离线模式。

## 8. UI-04 语音技能页

### 8.1 目标

语音技能页对应现有底部 `Sparkles` Tab，用于设置“说”和“改”的行为，不承载 ASR/LLM 密钥配置。

### 8.2 页面内容

#### 8.2.1 说：语音输入

- 显示当前触发模式；
- 选择按住说话或免提模式；
- 选择识别后是否自动打开预览；
- 选择确认后是否自动注入当前焦点输入框；
- 选择是否保留原始剪贴板内容并在注入后恢复；
- 显示当前默认 AI 整理模式的摘要和跳转配置入口。

#### 8.2.2 改：语音改写

- 开关：启用语音改写；
- 说明操作步骤：选中文字 → 按触发键 → 口述要求 → 确认结果；
- 选择是否自动捕获选区；
- 选择改写后是否直接替换选区，或始终先预览；
- 选择默认改写风格：正式、简洁、自然、保留格式；
- 显示无法获取选区时的回退方式：提示用户复制/重试。

#### 8.2.3 快捷操作

- 打开/隐藏面板；
- 暂停/恢复服务；
- 取消当前录音；
- 打开最近一次预览；
- 复制最近一次结果。

### 8.3 交互要求

- 所有开关和选择变更立即保存；
- 保存失败回滚，并显示 Toast；
- 关闭“语音改写”后，普通“说”流程不受影响；
- 关闭预览时，必须提供“确认后注入”或“取消注入”的明确结果。

### 8.4 验收标准

- 用户不进入服务配置页即可理解并修改“说/改”两种行为；
- 免提模式和按住说话模式的文案、底部提示和帮助说明保持一致；
- 语音改写功能关闭时，相关设置不可用但不消失，避免用户不知道功能存在。

## 12. UI-08 识别/改写预览弹窗

### 12.1 基础原则

继续使用现有 `PreviewPopup` 作为实现基础，不重新引入另一套弹窗组件。

弹窗必须支持两种业务模式：

- **识别预览**：原始 ASR 文本 → 预处理/AI 整理结果；
- **改写预览**：选区原文 + 用户语音指令 → LLM 改写结果。

### 12.2 识别预览

内容：

- 标题：`识别结果预览`；
- 来源标识：云端 ASR / 离线模型；
- 原始文本；
- 整理后文本编辑框；
- 当前整理模式；
- 可选“查看原始文本”；
- `确认并上屏`；
- `仅复制`；
- `取消`；
- `重新识别/重试`（仅在有可用音频时显示）。

确认前允许用户编辑最终文本。空文本禁止确认，并给出 inline 提示。

### 12.3 改写预览

内容：

- 标题：`改写结果预览`；
- `原选中文本`只读展示；
- `语音修改要求`只读展示；
- `改写结果`可编辑；
- 改写风格和模型摘要；
- `确认替换选区`；
- `复制结果`；
- `重新生成`；
- `取消`。

必须明确说明确认后会替换当前输入框的选区，避免用户误以为只是复制文本。

### 12.4 加载、失败和关闭行为

- 生成中：按钮禁用，显示进度文案，允许取消请求；
- LLM 失败：保留 ASR 原文，提供“跳过 AI 整理并使用原文”；
- 注入失败：保留最终文本，提供“复制到剪贴板”；
- 用户关闭弹窗：二次确认是否放弃当前结果（若文本已被编辑）；
- 确认成功：显示短暂成功提示并关闭弹窗，状态回到 `Idle`。

### 12.5 验收标准

- 用户可以在确认前编辑最终文本；
- 识别和改写的原文、结果、操作语义明确区分；
- 任何失败都不会丢失当前结果；
- 确认后状态、历史记录和注入结果同步更新。

## 13. UI-09 Toast、错误和阻断弹窗

### 13.1 Toast

Toast 显示在极简面板顶部内容区，不覆盖标题和底部 Tab。支持：

| 等级 | 颜色/图标 | 使用场景 |
| :--- | :--- | :--- |
| info | 蓝色 | 已切换离线、保存中、复制成功 |
| success | 绿色 | 配置保存成功、注入成功、模型下载完成 |
| warn | 橙色 | AI 整理失败，已使用原文；云端失败，已切换离线 |
| error | 红色 | API Key 无效、保存失败、注入失败 |

Toast 默认 3 秒自动消失；错误类 Toast 必须提供关闭按钮，必要时提供操作按钮。

### 13.2 阻断弹窗

以下场景使用模态弹窗：

- 没有可用麦克风；
- 需要的系统权限缺失；
- 数据库损坏或配置无法读取；
- 清空全部历史；
- 删除默认词条；
- 放弃已编辑的预览结果；
- 退出时仍在录音或识别。

弹窗必须包含：

- 明确标题；
- 简短原因；
- 用户可理解的下一步建议；
- 主操作和取消操作；
- 不使用技术堆栈替代用户文案。

### 13.3 错误信息映射

| 错误 | 小球反馈 | 面板反馈 | 可执行操作 |
| :--- | :--- | :--- | :--- |
| 无麦克风 | 灰色/红色 disabled | 阻断弹窗 | 打开麦克风设置、刷新设备 |
| 云端 ASR 失败 | 红色闪烁 | warn/error Toast | 重试、切换离线、进入配置 |
| LLM 失败 | 橙色短提示 | warn Toast | 跳过整理、重试、检查配置 |
| 离线模型缺失 | 灰色 disabled | error Toast | 打开模型管理下载 |
| 文本注入失败 | 红色提示 | error Toast | 复制到剪贴板、重试 |
| 配置保存失败 | 不改变小球 | error Toast | 重试，保留当前编辑值 |

## 16. 状态与交互协议要求

### 16.1 后端到 UI 的状态

UI 至少需要订阅以下状态：

- `Idle`；
- `Recording`；
- `Recognizing`；
- `Preview`；
- `Paused`；
- 错误状态或错误事件；
- 当前 ASR 来源：cloud/offline；
- 当前流程模式：speak/rewrite；
- 当前是否有待确认预览。

现有 `AppStatus` 可以继续作为基础状态类型，但为支持改写、错误和离线标识，UI 需求允许新增 `mode`、`error`、`provider` 等独立字段，避免把所有信息硬塞进一个状态枚举。

### 16.2 事件对应 UI 行为

| 事件 | UI 行为 |
| :--- | :--- |
| `runtime-state-changed` | 更新小球、面板状态圆点、状态按钮和底部提示 |
| `open-panel` | 显示并聚焦面板 |
| `minimize-panel` | 隐藏面板但保留后台运行 |
| `toast` | 在面板显示对应等级 Toast；必要时同步小球短提示 |
| `config-updated` | 更新当前窗口和其他窗口的配置展示 |
| 预览创建成功 | 显示 `PreviewPopup` 并进入 Preview 状态 |
| 确认注入成功 | 关闭预览、写入历史、回到 Idle |
| 注入失败 | 保留预览结果，显示复制/重试选项 |

### 16.3 窗口位置联动

- 面板打开时定位在浮球右侧或下方，避免遮挡浮球；
- 浮球拖拽后，已打开面板跟随移动；
- 面板关闭不改变浮球位置；
- 屏幕边缘附近自动调整面板方向，避免出屏；
- 位置保存到本地配置，读取失败时使用安全默认位置。

## 17. 通用视觉与交互规范

### 17.1 视觉

- 延续现有深色炭黑背景、`neutral` 色阶和绿色主强调色；
- 卡片保持约 12–22px 圆角；
- 设置行继续使用现有 `SettingRow` 结构；
- 开关继续使用现有 `ToggleSwitch`；
- 图标继续优先使用 `lucide-react`；
- 重要状态不能只依赖颜色，必须同时有图标或文字；
- 动画用于录音、识别、错误提示等状态，不用于装饰性大面积动效。

### 17.2 交互

- 所有按钮有 hover、pressed、disabled 状态；
- 所有图标按钮必须有 `title` 或可访问名称；
- 键盘可操作设置页、弹窗和列表；
- 弹窗打开时焦点进入主操作控件，关闭后恢复到触发控件；
- 破坏性操作必须二次确认；
- 保存失败不得清空用户输入；
- 加载状态不得出现多个同时可提交的主按钮。

### 17.3 文案

推荐使用以下统一术语：

- `识别`：ASR 转文字；
- `整理`：LLM 对识别结果的后处理；
- `改写`：针对选中文本的语音指令改写；
- `上屏`：写入当前焦点输入框；
- `确认并上屏`：确认预览并执行注入；
- `复制结果`：只写入剪贴板，不替换当前选区；
- `暂停服务`：暂停热键触发和自动录音，但保留面板/托盘。

## 19. 总体验收标准

### 19.1 基于现有 UI 的改造要求

- 现有悬浮球和极简面板仍是产品主入口；
- 现有四个底部 Tab 不删除，改为真实页面；
- 现有设置行不删除，补全点击、保存、错误和详情行为；
- 现有 `PreviewPopup` 不替换，扩展其识别和改写能力；
- 不保留面向用户可见的“待实现”占位提示；
- 旧的简单 `History` / `Settings` 页面功能统一到当前面板信息架构中。

### 19.2 核心操作验收

1. 用户打开应用后能看到小球，并能点击打开面板；
2. 用户能在面板中配置触发键、麦克风、ASR 和 LLM；
3. 用户按住 `Right Alt` 说话，松开后小球依次显示录音、识别和预览状态；
4. 用户能在预览弹窗编辑结果并确认上屏；
5. 云端不可用时，若本地模型存在，UI 能明确提示已切换离线；
6. 用户可以选中文字并完成一次语音改写；
7. 用户可以查看、搜索、复制和删除历史记录；
8. 用户可以管理个人词典；
9. 任意失败场景都有可理解的反馈和恢复操作；
10. 重启应用后，用户配置、主题、触发键、麦克风、词典和必要的历史数据仍然保持。

### 19.3 非功能验收

- UI 不泄露 API Key、Token、密码或完整敏感请求；
- 主流程不依赖浏览器开发预览模式中的 mock 状态；
- 浮球与面板状态由后端事件驱动，不能长期显示过期状态；
- 面板在 Windows 10/11 x64 的常见缩放比例下可读、可操作；
- 新增 UI 组件优先复用现有 `SettingRow`、`ToggleSwitch`、状态映射和主题变量。
